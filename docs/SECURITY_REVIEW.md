# Roque preliminary security review and audit scope

Date: 2026-11-04. Source baseline: `a0c34f6` plus pre-existing README/runner work. This is a planning-stage source review, with two offline reproductions. It is not a completed audit or a certification of deployed contracts, policies, infrastructure, or balances. The historical findings below have since been remediated in source; see [the finding-by-finding remediation tracker](SECURITY_REMEDIATION.md) and [release evidence](RELEASE.md). The original baseline descriptions are retained for traceability.

Scope includes Solidity execution/custody, Python interpretation/judgment, shared API/services, authentication, Neon persistence, both HTTP adapters, frontend transaction approval, background workers, Latch transport and deployment/CI. Native Rialo settlement is outside scope; the project owner's Rialo reference means current Latch use.

Severity describes potential impact given the stated preconditions. **Reproduced** means run against local code. **Source-confirmed** means the missing check/behavior is visible but an end-to-end exploit was not executed. Production exposure and exploitability need validation on isolated infrastructure.

Existing protections worth preserving include isolated per-user vault accounting, EIP-712 domain separation and used-intent nonces, on-chain input spend caps, owner checks on autonomous requests, conditional database claims before signing, reentrancy guards on vault/pool actions, and owner/expiry exits from commitments. The findings identify gaps in those boundaries; they do not imply anonymous callers can directly withdraw another user's vault.

## Additional audit work, separate from proven findings

- **Slippage economics:** `_checkSlippage` uses the same pool's current quote. That check bounds deviation from spot, not manipulation, external fair value, or loss under a compromised signer. Model an adversarial pool move and both action types; decide oracle deviation/TWAP/price-impact policy appropriate to the actual test tokens. Caps are spend limits, not profit or loss guarantees.
- **Asset accounting:** vault deposits and pool minting account nominal transfers. Current tokens are ordinary test ERC-20s. Before adding real assets, choose a standard-token-only policy or balance-delta handling for fee-on-transfer/rebasing behavior, malicious callbacks, unusual decimals and zero-output dust. Verify vault solvency and reserve/share invariants with fuzzing and stateful invariant tests.
- **Admin authority:** router pool registration, token/feed metadata and OrderBook configuration are owner-controlled. Record actual owners, upgrade/redeployment procedure, multisig/timelock policy and monitoring. A transaction signer holding admin authority is a larger boundary than a minimally funded gas payer. Do not call intentional owner powers an unproven exploit.
- **Database retry semantics:** [q](../packages/core/src/db/index.ts#L29) retries every transient query, including writes. Keyed writes may not double-spend, but lost responses to conditional `RETURNING` claims can return a different result on retry; increments and multi-row actions are not automatically idempotent. Test commit-then-timeout, not only throw-before-write. Classify retries, use stable operation keys and atomic transactions/outbox where needed. Review proposal acceptance/forking compensation for duplicate created objects after partial success.
- **Arming/cancellation races:** event/playbook status moves to `armed` before its hold confirms; workers and cancellation can observe the intermediate state. Add a non-executable `arming` state with recovery. Test hold accepted but response lost, cancellation during arming, cleanup failures, revoke during release and orphaned commitments.
- **Judgment provenance and conditional semantics:** evidence currently uses off-chain Google News RSS headlines supplied by the backend. Consensus does not independently prove source authenticity. Review dates/source coverage, prompt injection, ambiguous conditions, confidence policy, evidence digests and result equivalence. The interpreter prompt explicitly asks for `swap` when a requested limit pair lacks rWETH, while the deterministic normalizer rejects such a limit only if the model preserves `kind=limit`. Remove that downgrade instruction and require an explicit unsupported/clarification outcome; test conditional non-ETH commands against a live interpreter as well as deterministic fixtures.
- **Errors and client promises:** [Next error adapter](../apps/web/src/app/api/_util.ts#L17) returns raw exception messages to callers; Fastify sanitizes them. Browser errors sometimes say nothing changed after an uncertain server response. Sanitize both, retain internal correlation IDs and surface unknown transaction outcome accurately.
- **Scale and availability:** keeper scans all historical order IDs each tick; user order reads fetch the owner's complete list. Add bounded indexed work selection and per-operation failure isolation before inviting many partners. Verify production interpretation budgets and scheduler behavior against actual hosting configuration.
- **Dependencies and delivery:** review the lockfile's installed versions/advisories, Next/Privy/viem/GenLayer compatibility, vendored Solidity dependency provenance, secret hygiene and workflow permissions. CI definitions are present; their presence is not proof they passed in this session.
- **New API/MCP attack surface:** tenant/object isolation, OAuth audience/redirect/PKCE validation, approval-link theft, callback SSRF/rebinding, webhook replay, arbitrary calldata, origin/DNS checks, quotas, prompt injection, tool schemas and disconnect behavior. Keep partner secrets and wallet-signing material out of tool output/logs.

## Local evidence obtained

`python3 -m pytest packages/genlayer/tests -q` completed with **28 passing tests**. These use the repository's local GenLayer shim; they do not validate the SDK runtime, distributed consensus, network finality or deployed interpreter bytecode.

Both malformed-type cases were reproduced using existing code without modifying source:

```bash
python3 - <<'PY'
import json, sys
sys.path.insert(0, 'packages/genlayer')
from genlayer import set_prompt_response
from contracts.roque_interpreter import RoqueInterpreter
c = RoqueInterpreter()
set_prompt_response(json.dumps({
    'met': 'false', 'confidence': 'high',
    'rationale': 'The event has not happened.'
}))
c.adjudicate('offline-verdict', 'Example event condition', '{}')
print(c.get_adjudication('offline-verdict'))
set_prompt_response(json.dumps({
    'kind': 'swap', 'tokenIn': 'rUSDC', 'tokenOut': 'rWETH',
    'amount': '100', 'amountIsPercent': 'false', 'confidence': 'high'
}))
c.interpret('offline-percent', 'swap 100 USDC for ETH', '{}')
print(c.get_interpretation('offline-percent'))
PY
```

Observed results include `"met": true` and `"amountIsPercent": true`, respectively. No funds or network were involved.

`git diff --check` and document link/source-anchor, whitespace and code-fence checks passed. The local Node version was `v20.18.0`; workspace Node dependencies were absent, installed Corepack could not verify the pinned pnpm signing key, and `forge`/`uv` were not available on PATH. Full TypeScript/build/Foundry checks were therefore **not run**. Do not disable package-manager signature verification to make the baseline green; establish the supported toolchain first. Final verification details are recorded in the ignored root TASKS.md.

No production database inspection, deployed bytecode comparison, authenticated HTTP probing, Latch policy inspection, live broadcasts, or dependency audit was performed. User instructions and prior work were preserved.

## Audit completion criteria

1. Freeze the reviewed commit, deployed-address/version registry and supported asset/wallet scope. Create an endpoint permission matrix and explicit compromised-component threat model.
2. Turn the findings into independent reproductions on isolated infrastructure, including real local EVM execution and real SQL concurrency/crash tests. Preserve the original failing evidence, then retest fixes.
3. Run the existing CI checks, contract fuzz/invariant tests, API authorization tests, wallet integration flows, parser adversarial cases, secret/dependency scans and staged load/failure injection. Mock-heavy tests supplement rather than replace real boundary tests.
4. Review contract migrations, old-vault access and rollback before deployment. Verify public API + partner-wallet settlement end to end; separately verify the MCP and delegation paths being released.
5. Have an independent reviewer audit the financial authorization and new external execution boundaries. Close critical/high issues on exposed paths; document disposition and compensating constraints for any accepted medium/low finding.
6. Reconcile staging and deployed code/config/policies, run a limited partner pilot, and prepare monitoring, signer compromise response, token revocation, job recovery and owner-withdrawal runbooks.

Use a finding tracker with ID, affected version, preconditions, impact, reproducer, remediation PR, retest result, reviewer and release disposition. “All recorded findings addressed and release gates passed” is measurable; “all possible security gaps fixed” is not a defensible audit promise.
