## Discovered gaps addressed

- Owner order reads use the indexed getter and bounded pages rather than an unbounded owner array. Keeper progress survives restarts and scans at most 50 IDs/40 seconds per invocation.
- Quote/prepare writes use operation generations and leases. Plans retain canonical quote block/hash, exact allowances, amounts, recipient, economic bounds and expiry; the SDK independently decodes both actions.
- SDK disconnect omits JSON headers on empty requests; the Next adapter retains an absent payload. Real SQL/EVM regression verifies session revocation, and malformed JSON returns a stable client error.
- Approval links require separate owner proof, remain bound to their originating connection and become unavailable after revocation. Submitted hashes survive UI reload and report failures.
- First-party wallet limit preparation and receipt verification remain supported. Public v1 rejects conditional/limit/delegated actions.
- Schema migration is a single advisory-locked transaction. Reorg checkpoints are validated even when the indexer is caught up.
- Worker leases can be reacquired at their exact expiry timestamp. A deterministic SQL transaction regression verifies replacement ownership/generation, active exclusivity and stale-release fencing.
- Runtime and development dependencies are patched, including Next 15.5.29, Fastify 5.12.8, Privy 3.51.1, Zod 4.6.7, Vitest 4.1.12 and Vite 7.3.7. Targeted transitive updates remove the remaining advisories; unused GenLayer runtime lint tooling is removed. A minimal tracked decoder patch preserves WalletConnect CommonJS compatibility without changing the upstream security algorithm.
- Future OrderBook deployments reject disabled freshness, malformed rounds, zero/future timestamps and invalid feed decimals. The existing live OrderBook retains its immutable bytecode; release checks require its existing nonzero freshness configuration and successful price read.
- Earlier vault addresses, domain versions and blocks remain in the registry, with owner revoke/release/withdraw controls in the UI.

## Validation and remaining release gates

The dependency candidate passes 259 core tests, three wallet/image dependency checks, workspace TypeScript checks, the production Next build and the independent partner browser bundle. Both `pnpm audit --prod` and the full `pnpm audit` report zero vulnerabilities (724 production/optional and 817 total dependencies, 2026-11-04), without advisory suppressions. The unchanged contract/interpreter sources previously passed 100 Solidity and 54 Python tests with GenVM lint.

Core integration tests use PGlite plus Anvil deployed token/pool/router contracts; their English interpreter response is deterministic. Dependency checks exercise real WalletConnect parsing, bounded malformed-input decoding, ESM/CommonJS interoperability, MetaMask UUID generation/buffer validation and Sharp PNG/WebP resizing. The local Next build used genuine Google font files cached outside the repository because native Node HTTPS timed out; hosted builds use the normal Google fetch. Build warnings concern unused optional Solana/Tempo wallet integrations. The initial live release additionally verifies GenLayer consensus/binding and a real hosted wallet trade with canonical receipt/output matching, plus hosted OAuth/MCP and session revocation. Latest deployment evidence is in the release notes. These checks do not certify a third-party embedded wallet provider.

The separate optional scoped-delegation/direct-wallet-payout contract design is outside public v1 and remains gated by its own audit and migration. No mainnet asset support or unattended third-party wallet authority is advertised. Provider policy verification, an actual Claude connection, embedded-wallet certification and production operational monitoring require their own evidence; they are not inferred from local tests.
